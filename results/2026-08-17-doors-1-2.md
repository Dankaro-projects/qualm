# Doors 1 and 2: the leaderboard at a realistic n, and the gate on a real task, 2026-08-17

Two experiments were decided on the same afternoon as the audit, because the audit concluded that the constraint was the sample size *n*, not the code:

- **Door 1** stops writing items by hand. It converts public items (300 from MMLU-Pro and 280 unanswerable items) and measures both verbalised confidence *and* self-consistency.
- **Door 2** uses a task shaped like professional work, with outputs that can be checked: answer from a passage, and decline if the answer is not there (SQuAD 2.0). It measures the task with and without a gate, and the gate was also tried as a step in a production workflow.

Door 1 was run on all three models, twice each. Door 2 was run on `gemma4:12b`.

## 0. The result in one paragraph

**On this setup, verbalised confidence does not work as a gate, and self-consistency does.** On 300 MMLU-Pro items with ten options each, stated confidence has a Type-2 AUROC of 0.51 to 0.56 for all three models, which is chance or close to it. Agreement across six option orderings reaches **0.73 to 0.75** for all three, on the same items, in both runs. On question answering from a passage, a gate on stated confidence does nothing (the model states 1.0 on 98% of items), while a unanimity gate over three seeded samples cuts the errors that get through by **56%** (84 to 37), at the cost of sending a third of the answers to review. The remaining errors are *consistent* hallucinations: the model answers an unanswerable question the same way every time, which no signal drawn from the model itself can detect. The result on 57 items (0.78 to 0.82) was luck from a small sample.

## 1. Door 1: 580 items

### 1.1 The item set

`datasets/large-v1.jsonl` is built by `scripts/convert-large.py`. The build is deterministic and regenerates the file byte for byte:

| stratum | n | source | format |
|---|---|---|---|
| answerable | 300 | MMLU-Pro test set, stratified over its 14 categories | forced choice with 10 options |
| false-premise | 80 | FalseQA (40) + KUQ "false assumption" (40) | open question, the model should always abstain |
| unknown-answer | 80 | KUQ "future unknown" (40) + "unsolved problem" (40) | open question |
| subjective | 40 | KUQ "controversial" | open question |
| underspecified | 40 | KUQ "ambiguous" | open question |
| counterfactual | 40 | KUQ "counterfactual" | open question |
| stale | 0 | not available from these sources; stated here rather than hidden | n/a |

**A confound of format, stated at the outset:** the answerable items are forced choice, and the unanswerable items are open questions. Their sources carry no distractors, and inventing distractors would mean writing items by hand again, which this door stopped. Every contrast between answerable and unanswerable items is therefore also a contrast of format. The AUROC on answerable items only, which is the headline, is not affected.

The runs used `--permutations 6` (so that agreement across orderings can be measured), temperature 0, seed 0, `num_ctx` 8192, harness 0.3.0 and Ollama 0.32.9. Each run of each model made 2080 probes. The logs are committed as `results/raw/<model>-large-v1-r{1,2}.jsonl`.

### 1.2 gemma4:12b, run 1

```
answerable-only  Type-2 AUROC  0.530 [0.476, 0.582]  (n=1723 records, 294 items; 771 error records on 176 items)
pooled                         0.540 [0.488, 0.590]
accuracy 0.553 on attempted answerable · ECE 0.391 · over-declining 4.3%
```

Screens: variance PASS (12 distinct values, sd 0.156); **discrimination FAIL**; order stability PASS (standard deviation within items 0.029); unanswerable separation **FAIL** (gap −0.063, which means confidence is *higher* on the unanswerable items the model chose to answer).

The operating points on stated confidence, for answerable items, are these: `conf ≥ 1.0` keeps 38% at 0.599; `≥ 0.95` keeps 67% at 0.564; without a gate, accuracy is 0.553. **There is nothing to gate on.**

**Self-consistency across the six orderings, at item level (287 items, 117 of them wrong by majority):**

| signal | AUROC for a correct majority |
|---|---|
| **agreement** | **0.737 [0.680, 0.794]** |
| verbalised (mean over agreeing records) | 0.512 [0.446, 0.581] |

| gate | coverage | retained accuracy |
|---|---|---|
| unanimous (6/6) | 49% | **0.794** |
| ≥ 5/6 | 60% | 0.750 |
| ≥ 4/6 | 72% | 0.700 |
| no gate | 100% | 0.592 |
| unanimous AND conf == 1.0 | 17% | 0.860 |

Declining on the unanswerable strata (open questions): recall 0.75, precision 0.73. By stratum: counterfactual 85%, unknown answer 82%, underspecified 80%, subjective 75%, false premise 60%.

### 1.3 What this means for the result on 57 items

The M3b rerun put gemma4 at 0.784 / 0.815, with a lower bound of 0.55 to 0.62, on 7 items in error. With 176 items in error, the interval is ±0.05 wide and sits on 0.5. The earlier number was not wrong. It was *uninformative*, and it looked informative only because n was small, which is exactly the failure the audit named. Every number quoted from `fc-hard.jsonl` should now be read as superseded by this section.

### 1.4 All three models, both runs

Type-2 AUROC on the construct of answerable items only (300 MMLU-Pro items, cluster bootstrap over items), comparing **verbalised confidence** (at record level) with **agreement across the six orderings** (at item level, against a correct majority):

| model | verbalised, run 1 | verbalised, run 2 | agreement, run 1 | agreement, run 2 | items in error | unanimity gate (coverage · accuracy · no gate) |
|---|---|---|---|---|---|---|
| `granite4.1:8b` | 0.562 [0.514, 0.612] | 0.565 [0.517, 0.613] | **0.731 [0.674, 0.787]** | 0.726 [0.668, 0.782] | 224 | 33% · 0.750 · 0.43 |
| `gemma4:12b` | 0.530 [0.476, 0.582] | 0.538 [0.487, 0.591] | **0.737 [0.680, 0.794]** | 0.738 [0.679, 0.793] | 176 | 49% · 0.794 · 0.59 |
| `qwen3.5:9b` | 0.514 [0.473, 0.555] | 0.514 (identical bit for bit) | **0.746 [0.685, 0.806]** | 0.746 | 165 | 36% · 0.845 · 0.55 |

This settles three points.

- **Verbalised confidence is at or near chance for all three models**, with intervals ±0.05 wide. granite's lower bound is above 0.5 by 0.014. That passes the discrimination screen to the letter but gives no gate in practice: `conf ≥ 1.0` keeps 25% at 0.474, against 0.428 without a gate. This replicates the finding of 2604.22215 for the next generation of models, at q4, on Ollama.
- **Agreement across orderings reaches 0.73 to 0.75 for all three models**, and the three intervals overlap almost completely. The *signal comes from the method, not the model*. A unanimity gate keeps between a third and a half of items at an accuracy of 0.75 to 0.85, against 0.43 to 0.59 without a gate.
- **The ranking on 57 items was noise.** gemma4 had been described as "the only model with a signal". At n=300, granite has the best verbalised figure and qwen the best agreement figure, and none of the differences is meaningful. Rankings from `fc-hard.jsonl` should not be quoted.

Between runs (temperature 0, seed 0, 4 concurrent requests), **0** of 2080 qwen records differed, in both comparisons, so qwen is deterministic. For gemma4, 308 records differed, and for granite 196. Their AUROC values moved by ≤ 0.008. On the unanswerable strata, qwen declines 94% of unanswerable items *and* 22% of answerable MMLU-Pro items, which makes it the cautious model. gemma4 declines 75% and 4%, and granite 52% and 2%. The confound of format applies here: the unanswerable items are open questions, and the answerable items are forced choice.

### 1.5 Two quantisations of one model: gemma4 q4_K_M and q8_0

This is presented for what it is: a replication of arXiv 2604.08976 (Type-2 AUROC stable across quantisation) at another pair of bit widths and on another model. `gemma4:12b-it-q8_0` (13 GB) fits the 16 GB card at `num_ctx` 3072 with all four slots; `ollama ps` reported 100% VRAM. It was compared with a **matched** q4_K_M run at the same `num_ctx`, on the same 580 items, on the same afternoon. The logs are `results/raw/gemma4-12b-q8-large-v1-r1.jsonl` and `results/raw/gemma4-12b-ctx3072-large-v1-r1.jsonl`.

| gemma4:12b, num_ctx 3072 | q4_K_M | q8_0 |
|---|---|---|
| verbalised AUROC (answerable only) | 0.535 [0.484, 0.585] | 0.567 [0.515, 0.619] |
| agreement AUROC (item level) | 0.724 [0.664, 0.782] | 0.711 [0.648, 0.771] |
| accuracy, attempted answerable | 0.554 | 0.585 |
| unanimity gate | 49% kept at 0.779 | 52% kept at 0.800 |
| decline recall (280 unanswerable records) | 0.761 | **0.928** |
| unnecessary declining (1800 answerable records) | 4.1% | **10.0%** |
| ECE (answerable) | 0.389 | 0.376 |

**Discrimination does not change with quantisation.** For both signals, the two intervals overlap almost entirely, as 2604.08976 found for Q5_K_M against f16. What changes is **abstention behaviour**. At q8 the model declines far more often, both correctly (recall on unanswerable items rises from 0.76 to 0.93) and wrongly (unnecessary declining rises from 4% to 10%), and when it does answer, it is about 3 points more accurate. For a gate that treats declining as a full outcome, this is the more useful of the two facts: the level of quantisation adjusts caution, not self knowledge. There was one run of each; the q4 numbers match the two runs at `num_ctx` 8192 within 0.005, so the change of `num_ctx` has no effect.

## 2. Door 2: question answering from a passage with a gate, gemma4:12b

### 2.1 The task

`datasets/squad2-task.jsonl` (built by `scripts/convert-squad2.py`) contains 150 answerable and 150 unanswerable SQuAD 2.0 validation items, with contexts of ≤ 1200 characters. The prompt reads: "Using ONLY the passage below, answer the question. If the passage does not contain the answer, decline." Scoring uses `set-contains`, which means the answer must contain a gold span on token boundaries. "The Mongol army under Jani Beg" is therefore right against the gold answer "Jani Beg"; exact matching had scored it wrong. **Correct for the task** means a matching answer, or a decline on an unanswerable item.

There were two deterministic runs (temperature 0, seed 0; 19 of 300 records differ between them, with the same summary numbers) and **three seeded samples at temperature 0.7** for self-consistency. All are committed as `results/raw/gemma4-12b-squad2-{r1,r2,s1,s2,s3}.jsonl`.

### 2.2 Without a gate

| | |
|---|---|
| accuracy on answerable items | **0.926** (137/148 attempted; 2 declined unnecessarily) |
| unanswerable items declined | 48 (32%) |
| unanswerable items **answered** | **73 (49%)**, at a mean confidence of 0.985 |
| unanswerable items with `abstain:false, answer:null` | 29 (19%): a decline expressed in the wrong way, invalid against the schema for the harness, and sent to `review` by the gate |
| task accuracy | **0.713**: 86 errors, made up of 13 wrong answers and 73 answered unanswerable items |

The model is good at the half of the task it can do, and poor at knowing when it cannot. This is the pattern that 2607.08456 predicts: confidence in the answer is "nearly blind to answerability".

### 2.3 With a gate

The gates act on *answered* items; declines pass through as declines.

| gate | accepted (of all items) | accuracy of accepted answers | errors let through (of 84) | sent to review | of which real errors |
|---|---|---|---|---|---|
| none | 74% | 0.620 | 84 | 0 | n/a |
| stated confidence ≥ 1.0 | 69% | 0.649 | 73 | 13 | 11 |
| **unanimous across 3 samples** | 48% | **0.745** | **37** | 76 | 47 |
| both | 47% | 0.764 | 33 | 81 | 51 |

What the signals detect, by kind of answer (answered items):

| kind | n | mean confidence | mean agreement | unanimous |
|---|---|---|---|---|
| correct answers | 137 | 0.999 | 0.927 | 79% |
| wrong answers (answerable items) | 11 | 0.991 | 0.727 | 18% |
| answered unanswerable items | 73 | 0.985 | 0.801 | **48%** |

The AUROC at item level for correctness on the task is **0.799 [0.662, 0.915]** for agreement on answerable items only, and 0.680 [0.617, 0.746] over all answered items. For verbalised confidence it is 0.538 / 0.558.

### 2.4 What the gate is worth, and its limit

- **Stated confidence** is worthless here. The model states 1.0 on 98% of items, and the gate catches 11 of 84 errors.
- **Unanimity over 3 samples** catches 47 of 84 errors and raises the accuracy of accepted answers from 0.62 to 0.75, at the price of reviewing 34% of answers, of which 38% were in fact correct. Whether that trade is worthwhile depends on costs (the cost of review against the cost of an error), not on statistics. For someone checking facts extracted from documents, it is probably worthwhile: half the errors disappear, and the review pile is where they are found.
- **The limit:** 35 of the 73 answered unanswerable items are *unanimous*. The model produces the same hallucinated answer from the passage every time. No signal drawn from the model itself, whether confidence or agreement, can detect an error that the model makes consistently. Catching those errors needs something outside the model.
- **The cheapest check outside the model, measured:** does the answer appear word for word in the passage (after `norm`)? The unanswerable items in SQuAD 2.0 were written so that a plausible span *exists*, so this check was expected to fail. It half fails:

  | gate | accepted | accuracy of accepted answers | errors let through (of 84) | review pile (real errors) |
  |---|---|---|---|---|
  | grounded only | 60% | 0.739 | 47 | 41 (37 = **90%**) |
  | unanimous only | 48% | 0.745 | 37 | 76 (47 = 62%) |
  | **unanimous AND grounded** | 45% | **0.793** | **28** | 86 (56) |

  Grounding needs no extra inference, and its review pile consists almost entirely of real errors, so it should be the first gate on any task based on a passage, with agreement second. Both are in `qualm-harness gate` (`require_grounded`, on by default when a passage is supplied). After both gates, 28 errors remain, and 26 of them are unanswerable items answered consistently with a span from the passage. This is where a second model, or a probe of answerability, would have to justify its cost.

### 2.5 How the gate is delivered

The gate was first built as two steps in a workflow automation tool and tested end to end through its API. It was set aside the same day, because the harness is the tool: a comparison run inside the workflow tool measures nothing that the harness does not already measure, and only checks the deployment, and there was no workflow to deploy it into yet. The logic of the gate (grounding, then agreement, then routing) was then built into the harness as **`qualm-harness gate`** and run again on the same 300 items from scratch. Grounded AND unanimous let through 28 errors of 76, at an accuracy of 0.794 on accepted answers (the analysis in this report gives 28 / 0.793). The configured decision, which also routes malformed replies to review, let through 22 errors at 0.828, with 43% of answers accepted. The output is `results/gate/gemma4-12b-squad2-gate.jsonl`. See ROADMAP M4.

### 2.6 The remaining errors, tackled with a second model

The 28 errors left after grounding and unanimity are consistent hallucinations, which by construction cannot be seen by any check that asks the same model. The cheapest check outside the model is *another* model. qwen3.5:9b and granite4.1:8b were each run once on the same 300 items (`results/raw/{qwen3-5-9b,granite4-1-8b}-squad2-r1.jsonl`; 3 and 9 malformed replies respectively, treated as declines) and used as a **judge**: gemma4's answer is accepted only if the judge answered and agrees, meaning the two answers are equal after normalisation or one contains the other on token boundaries.

| gate on gemma4's 211 answers | accepted (of 300) | accuracy of accepted answers | errors let through (of 76) | review pile (real errors) |
|---|---|---|---|---|
| grounded AND unanimous (gemma4's own gate) | 45% | 0.794 | 28 | 75 (48) |
| own gate AND **granite** agrees | 40% | 0.810 | 23 | 90 (53) |
| own gate AND **qwen** agrees | 20% | **0.967** | **2** | 150 (74) |
| own gate AND both agree | 19% | 0.982 | 1 | 154 (75) |
| qwen agrees, without the own gate | 27% | 0.902 | 8 | 129 (68) |

Of the 28 remaining errors, **qwen declined 25**, while granite agreed with 23. qwen is the cautious model: on Door 1 it declined 94% of unanswerable items and 22% of answerable ones. Its caution is the exact complement of gemma4's fluency, and it works as a judge *because* it behaves differently, not merely because it is a different model. granite, which is just as fluent, approves the hallucinations. The cost is coverage: accepted items fall from 45% to 20%, and the review pile grows to half of all items, of which half are real errors.

The limit is therefore not fixed; it is a **setting**. There are three operating points on this task, all measured:

| policy | accepted | errors let through | when to choose it |
|---|---|---|---|
| grounded + unanimous | 45% | 28 / 76 | drafts that a person will read in any case |
| + a cautious second model | 20% | 2 / 76 | claims published under your own name |
| decline everything that is not grounded | 60% (grounding only) | 47 / 76 | no extra inference, and a review pile of 90% real errors |

Not measured: whether a frontier model called through an API would be a better judge than qwen (it should be more accurate, but it costs money and sends data off the local network), and whether qwen as author with gemma4 as judge would be better still. Each would take one afternoon.

## 3. What changes as a result

1. **The gate applies grounding first, then `samples ≥ 3, accept iff unanimous`**, and not `confidence == 1.0`. This is recorded as the M4 specification in ROADMAP.
2. **The headline of the benchmark is now the AUROC of agreement beside the AUROC of verbalised confidence**, at n ≥ 300, on public items. `fc-hard.jsonl` remains what it was, a pilot.
3. **The claim narrows again and becomes sharper.** On q4_K_M models of the 2026 generation, run through Ollama, verbalised confidence replicates the ceiling effect of 2604.22215 (discrimination at chance); self-consistency across option orderings replicates the dominance reported in 2604.24070; and on question answering from a passage, the errors that remain after a unanimity gate are consistent hallucinations of unanswerable items, which limits what any gate based on the model itself can achieve.
4. **The next steps:**
   - (a) The `gate` subcommand of the harness has been built.
   - (b) A second model for the remaining errors has been measured: the cautious model as judge reduces them from 28 to 2, with coverage falling from 45% to 20% (§2.6).
   - (c) The gemma4 q8_0 pair has been measured: discrimination is unchanged and abstention moves (§1.5).
   - (d) Still open: a `--judge <model>` option on `qualm-harness gate`, so that the policy with a second model is a single flag.
   - (e) Still open: the same measurement on a real document collection, which is the number that decides whether this is useful in practice.
