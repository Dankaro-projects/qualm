# Baseline observations, 2026-08-17

This is not a qualm run. It records **evidence gathered earlier**, while choosing a local model for automated workflows, before this project existed. It is recorded here because it motivated the project, and because it already casts doubt on validity screen #1.

**Hardware:** an RTX 5060 Ti with 16 GB (Blackwell). **Server:** Ollama 0.32.9. **All models are q4_K_M** unless noted. Settings: `OLLAMA_NUM_PARALLEL=4`, `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`.

## What was run

The task was an "expert panel". Four personas (optimist, contrarian, infrastructure engineer and risk officer) answered one contested question: *should a small team host its own LLM inference?* Each returned strict JSON against a schema with `verdict` (an enum), `confidence` (a number), `key_points` (an array) and `main_risk`.

The four personas ran **concurrently**, and the exercise was repeated for 3 to 4 rounds.

**An important limitation:** the question has **no ground truth**. These numbers therefore say nothing about *accuracy* or AUROC. They inform exactly one thing, the **distribution of stated confidence**, and that turned out to be the point.

## The finding that motivated this project

The table below lists every `confidence` value observed across three models. The conformance table above sums to 40 conforming samples, not 36. The raw data was not kept, so the true count cannot be recovered, and the figure "36" should be treated as approximate wherever it is quoted.

| Model | Values observed | Min | Max |
|---|---|---|---|
| `granite4.1:8b` | 0.98, 0.87, 0.92, 0.87, 0.92, 0.73, 0.87, 0.87, 0.87, 0.87, 0.92, 0.87 | **0.73** | 0.98 |
| `qwen3.5:9b` | 0.89, 0.87, 0.98, 0.87, 0.98, 0.85, 0.85, 0.94, 0.98, 0.87, 0.94, 0.89 | **0.85** | 0.98 |
| `gemma4:12b` | mostly 0.85, some 0.92 / 0.95 | **0.85** | 0.95 |

**No value fell below 0.73. The range was 0.25 wide, on a contested question with no correct answer.** Two of the three models never went below 0.85.

This reproduces the 80 to 100% clustering of verbalised confidence reported by Xiong et al., by accident and on quantised local weights. In practice, the `confidence` field was **decorative**.

**The consequence for M1.** Validity screen #1 tests *variance*, and on this evidence it may fail outright. A field that is almost constant cannot discriminate anything, yet it will still yield an AUROC near 0.5, which reads as "measured, weak signal" rather than "not measurable". This is exactly why the screen comes before the leaderboard.

**Threshold calibration from these numbers.** The variance screen tests the standard deviation *and* the number of distinct values, and the second test is the one that will matter. Confidence spread over `[0.73, 0.98]` has a standard deviation of about 0.07, so it passes a floor of 0.05. However, `granite4.1:8b` emitted only **four distinct values** across twelve samples (0.73, 0.87, 0.92, 0.98), and `gemma4:12b` effectively **two**. The models round their own confidence onto a handful of values, so `min_distinct` is the test that discriminates, and a threshold of 4 sits exactly at the observed boundary.

## Persona convergence, a separate problem

`gemma4:12b` collapsed. By round two, **every** persona returned `mixed` / `0.85`, including the one instructed to act as a contrarian. `granite4.1:8b` did not collapse: its contrarian returned `oppose` in every round (0.98, 0.92, 0.87), while its optimist returned `support`.

This is distinct from calibration, but relevant. If the dissent in a panel is only nominal, an aggregate over the panel is one opinion presented four times. It deserves its own metric later. **Diversity is not the same as calibration and should not be pooled with it.**

## `gpt-oss:20b`, excluded with cause

This model scored **0/12**, and configuration cannot fix it. Its output was *corrupt*, not merely placed in the wrong field:

```
The user says: ", "verdict" : "oppose", "confidence": 0.6, ...
```

It uses OpenAI's Harmony channel format, which conflicts with the grammar constrained decoding in llama.cpp. It was tested in four ways: `think:false`, `think:"low"`, `format:"json"`, and the schema alone. All four failed.

This case differs from qwen3.5, which *also* scored 0/12 at first but was **complying perfectly**: its JSON was intact in the `thinking` field, and `response` was empty. Setting `think:false` moved the output, and the model then scored 12/12. The symptom was the same and the cause was opposite: one is a limitation of the model, and the other was a bug in the harness.

## Throughput, for planning run budgets

Aggregate tokens per second, with 4 concurrent clients, all at `100% GPU` unless noted:

| Model | @16K ctx | @32K ctx | @64K ctx |
|---|---|---|---|
| `granite4.1:8b` | **123** | 54 *(20%/80% CPU/GPU, spilled)* | 27 *(spilled)* |
| `qwen3.5:9b` | 51 | 51 | **50** *(still 100% GPU)* |
| `gpt-oss:20b` | 100 | 63 *(10% CPU, spilled)* | n/a |

One result runs against intuition and matters when sizing a run. At 16K with 4 slots, `granite4.1:8b` (a 5.3 GB download) occupies **11 GB** in memory, while `qwen3.5:9b` (a 6.6 GB download) occupies **6.1 GB**. The download size does not predict the memory footprint; the design of the KV cache does. Qwen holds 64K across 4 slots in 7.2 GB, with about 7 GB to spare.

**For planning:** probe sets with long contexts should use `qwen3.5:9b`, and high volumes of short probes are about 2.4x cheaper on `granite4.1:8b`.

## Corrections

An earlier version of this report, dated 2026-08-17, said the threshold reasoning had been *"verified against a synthetic control"*. No such control exists in this repository. The check was run in a scratch file that was never committed, so the claim could not be reproduced. The sentence also did not support its own conclusion: uniform noise over the same range passes on *both* the standard deviation and the number of distinct values, so the distinctness test does not catch it either. What does catch real data is that **models round their own confidence onto about 4 values**, which is visible in the table above and does not appear in synthetic noise.
