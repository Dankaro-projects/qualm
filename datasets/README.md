# Probe items

Items are treated as data, not code. They are kept under version control with stable identifiers, because a change to an item invalidates every earlier result, and that change must therefore be visible in a diff. The only text the model sees that is not stored here is the instruction wrapper (`PROMPT_TEMPLATE` and `CHOICE_SUFFIX` in `crates/qualm-harness/src/run.rs`). It is versioned by hand through the `--prompt-set` tag. If the template changes without a new tag, old and new runs would carry identical provenance, so always change the tag with the template.

Each file is JSONL, with one item per line, and conforms to [`../schemas/probe-item.schema.json`](../schemas/probe-item.schema.json).

## Every item is stratified

Every item carries a `category` and a `domain`. Both are required, for specific reasons:

- **`domain`**: the effect of quantisation on calibration is reported at the level of domains. A single pooled number would hide the effect the project expects to find.
- **`category`**: whether a model declines depends strongly on why a question cannot be answered. Pooling unknown answers with false premises would average away the most informative differences.

The taxonomy follows AbstentionBench, with one category added by this project:

| `category` | `answerable` | What it tests |
|---|---|---|
| `answerable` | true | Basic competence and confidence |
| `unknown-answer` | false | A question that cannot be known; the model should decline |
| `underspecified` | false | Missing context; the model should ask rather than guess |
| `false-premise` | false | The question contains something untrue |
| **`coherent-false-premise`** | false | **Added by this project**: a premise that is internally consistent and false |
| `subjective` | false | There is no fact of the matter |
| `stale` | false | The answer has changed since the model was trained |

The converted sets also use `counterfactual` (from KUQ) and `missing-context` (the unanswerable half of SQuAD 2.0).

### Why `coherent-false-premise` exists

This category tests the coherence hypothesis, the mechanism that Kahneman describes: confidence follows the internal consistency of the evidence rather than its quality.

The prediction is that confidence on these items should be high and flat, and statistically indistinguishable from confidence on answerable items, because the model's evidence is coherent and simply wrong. If confidence separates answerable items from unknown answers but not from coherent false premises, that is direct evidence that the signal tracks coherence rather than correctness.

Write these items so that a plausible but false premise is stated calmly and consistently, with no hints, no hedging and nothing that a keyword filter could detect.

## Scoring must be mechanical

The field `scoring.method` must allow a machine to decide correctness on its own. An item that needs a person or a judge model to grade it does not belong in the set, because a judge brings its own calibration as a confound, and its cost has no limit.

For unanswerable items, use `always-abstain`: any substantive answer is wrong by construction.

## Paraphrase pairs

Validity screen 3 tests whether confidence stays stable when a question is reworded. To create a pair, set `paraphrase_of` to the identifier of the original item, keep the meaning and the `scoring` identical, and change the wording. About 10% of items should have a pair: enough to estimate stability, and cheap enough to write.

## The sets

| File | Purpose | Status |
|---|---|---|
| `pilot.jsonl` | The M1 validity screen: 102 open questions, 46 answerable | Generated by `scripts/make-pilot.py`. It cannot measure AUROC, because no model got an answerable item wrong |
| `fc-hard.jsonl` | M3: 57 forced choice items, 36 answerable, 6 paraphrase pairs, and 6 unanswerable strata of 1 to 5 items | Generated by `scripts/make-fc.py`. Too small for narrow confidence intervals; see the roadmap, M2 |
| `large-v1.jsonl` | The 300 item benchmark: 300 answerable MMLU-Pro items and 280 unanswerable items in 7 groups of 40 | Generated by `scripts/convert-large.py` |
| `squad2-task.jsonl` | The passage task for the gate: 300 SQuAD 2.0 items, half answerable and half without an answer in the passage | Generated by `scripts/convert-squad2.py`, which also writes `squad2-task.eval.json` |

Every set regenerates byte for byte from its script. Do not edit the JSONL files by hand; change the script and run it again.

**Every distractor on an unanswerable item must be a substantive wrong answer.** The item `fc-fp-king-usa` once offered "there is no such office", which is the correct rejection of the premise. All three models chose it with confidence 1.0 and were scored as wrong. Every stale item must also have an option set in which the answer at training time is now wrong. An item with only one defensible answer (`fc-stale-tallest-building`) tests nothing, and it was removed.

## Example

```json
{"id": "geo-capital-france", "prompt": "What is the capital of France?", "answerable": true, "category": "answerable", "domain": "geography", "difficulty": "easy", "scoring": {"method": "exact", "answer": "Paris"}, "source": "authored"}
{"id": "geo-capital-atlantis", "prompt": "What is the capital of Atlantis?", "answerable": false, "category": "false-premise", "domain": "geography", "scoring": {"method": "always-abstain"}, "source": "authored"}
```
